# COBOL 学生アカウント管理システム テスト計画

## 目的と前提

このテスト計画は、現行 COBOL アプリケーションの動作を業務関係者と確認し、将来の Node.js 移行時に単体テストおよび結合テストへ引き継ぐためのものです。

- 各テストケースは、特に記載がない限り新しいプロセスで開始する。
- 初期残高は `1000.00` とする。
- 金額は整数部 6 桁、小数部 2 桁（`PIC 9(6)V99`）で扱う。
- `Actual Result` と `Status` は実行後に記入する。未実施のテストは `Status` を空欄のままにする。
- 「現行挙動の確認」は、Node.js 移行時に同じ挙動を再現するか、業務仕様として変更するかを決めるための確認事項である。

## 移行時の確認事項

- 現行 COBOL の表示文言を互換対象にするか、Node.js の API 応答や UI 文言へ置き換えるかを決める。
- 入金・出金でゼロや負数を許可しない業務ルールを明文化し、Node.js 側で入力検証を追加するか決める。
- `PIC 9(6)V99` の上限、丸め、金額計算の精度を Node.js 側で再現する。
- COBOL の実行中メモリ保持を、Node.js では適切な永続化ストアへ置き換えるか決める。
- 残高不足時に残高が変更されないことを、単体テストと API の結合テストの両方で確認する。
